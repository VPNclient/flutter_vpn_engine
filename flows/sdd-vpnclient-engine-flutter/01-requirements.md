## Problem Statement

Flutter applications need a unified, cross-platform interface to establish VPN connections using various VPN protocols (V2Ray, SingBox, WireGuard) and tunneling drivers. Without this abstraction, developers must implement platform-specific VPN code for each target OS (Android, iOS, Windows, Linux, macOS), leading to code duplication and inconsistent behavior.

## User Stories

### Primary

**As a** Flutter app developer
**I want** a unified VPN engine API
**So that** I can implement VPN functionality once and deploy to all platforms

**As a** VPN app developer
**I want** to switch between VPN cores (SingBox, LibXray, V2Ray)
**So that** I can choose the best protocol implementation for my use case

**As a** VPN app user
**I want** real-time connection status and traffic statistics
**So that** I can monitor my VPN connection state

### Secondary

**As a** developer
**I want** subscription URL support
**So that** I can let users import server lists from providers

**As a** developer
**I want** server latency testing
**So that** I can help users select the fastest server

## Acceptance Criteria

### Must Have

1. **Given** a VPN configuration with core and driver settings
   **When** calling `initialize(config)`
   **Then** the native engine is created and ready for connection

2. **Given** an initialized engine
   **When** calling `connect()`
   **Then** VPN connection is established and status changes to `connected`

3. **Given** an active VPN connection
   **When** calling `disconnect()`
   **Then** VPN is terminated and status changes to `disconnected`

4. **Given** an active VPN connection
   **When** subscribing to `statsStream`
   **Then** traffic statistics (bytes sent/received, latency) are emitted periodically

5. **Given** a V2Ray share URL (vmess://, vless://, trojan://, ss://, socks://)
   **When** parsing with `parseV2RayURL()`
   **Then** valid configuration JSON is generated for the core

### Should Have

- Subscription URL fetching and server list management
- Server latency ping functionality
- Per-app VPN routing (Android)
- Logging with configurable levels

### Won't Have (This Iteration)

- Built-in UI components
- Kill switch implementation (platform-dependent)
- Split tunneling configuration UI

## Constraints

- **Technical**: Must work with dart:ffi for native C++ communication
- **Performance**: Connection establishment within 5 seconds
- **Platform**: Android 6.0+, iOS 12.0+, Windows 10+, Linux (modern distros), macOS 10.15+
- **Dependencies**:
  - sing-box, libxray, v2ray-core binaries
  - hev-socks5-tunnel, tun2socks libraries

## Functional Requirements

### FR-1: Core Management

| ID | Requirement |
|----|-------------|
| FR-1.1 | Support SingBox core with built-in TUN |
| FR-1.2 | Support LibXray core (requires external driver) |
| FR-1.3 | Support V2Ray core (requires external driver) |
| FR-1.4 | Support WireGuard core with built-in TUN |

### FR-2: Driver Management

| ID | Requirement |
|----|-------------|
| FR-2.1 | Support HevSocks5 driver as default |
| FR-2.2 | Support Tun2Socks driver as alternative |
| FR-2.3 | Auto-detect driver requirement based on core type |

### FR-3: Connection Management

| ID | Requirement |
|----|-------------|
| FR-3.1 | Expose connection lifecycle: initialize, connect, disconnect, dispose |
| FR-3.2 | Provide reactive status stream with state changes |
| FR-3.3 | Provide reactive statistics stream with traffic metrics |
| FR-3.4 | Support connection timeout configuration |

### FR-4: Subscription Management

| ID | Requirement |
|----|-------------|
| FR-4.1 | Fetch and parse subscription URLs (base64 encoded) |
| FR-4.2 | Parse V2Ray share URLs (vmess, vless, trojan, ss, socks) |
| FR-4.3 | Test server latency via TCP ping |
| FR-4.4 | Select and connect to specific servers |

## Non-Functional Requirements

### NFR-1: Performance

- Connection establishment < 5 seconds
- Stats polling interval: 1 second
- Native FFI overhead < 1ms per call

### NFR-2: Reliability

- Graceful handling of connection failures
- Automatic resource cleanup on dispose
- Thread-safe native engine operations

### NFR-3: Portability

- Single Dart API for all 5 platforms
- Platform-specific code isolated to native layer
- No Flutter UI dependencies in core library
